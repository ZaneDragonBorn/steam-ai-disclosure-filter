## Verdict

**Not ready to submit.** The local implementation passes its functional regression suite, but eligibility, licensing, UI acceptance and release verification remain unresolved. In particular, the documented development history appears incompatible with the rule against primarily AI-generated plugins. An AI-assistance disclosure does not by itself satisfy that rule. Obtain an explicit eligibility assessment from the maintainers before investing in a submission.

This review covers the current **working tree**, version 0.7.12, with manifest ID `dev.zanedb.ai-disclosure-filter`. It is not an approval, security certification, or review of a committed release. No production source was changed, no local Steam install was updated, and no upload, comment or PR was made.

## Issues and recommended corrections

### Before claiming submission readiness

1. **Resolve eligibility first.** The AI-origin concern is not a formatting defect that can be repaired by making code look different. Seek a candid maintainer assessment covering both origin and client specificity. No such contact has been sent by this review.
2. **Select licensing and establish release provenance.** Add full license text and applicable notices. Once authorized to publish, make the source accessible and pin a complete commit. Include `webview/steam/wishlist.ts`, `webview/ui/wishlist.ts` and `tests/wishlist.test.ts`, currently untracked. Do not submit only the generated archive.
3. **Resolve custom UI exceptions.** `frontend/ui.tsx` uses browser details/summary; `frontend/information.tsx` uses styled classification-card wrappers; `frontend/index.tsx` uses native buttons with custom tab semantics because the SDK Tabs export stayed on a loading placeholder in prior live testing. `webview/ui/sidebar.ts` and `wishlist.ts` build storefront controls directly. None of those facts automatically grants a policy exception. Use supported equivalents where they meet the need and explain remaining cases to reviewers.
4. **Test the exact release on both Steam channels and declared platforms.** Include native settings, keyboard/controller focus, pointer reorder previews, Wishlist compact/expanded modes, native options/chips/ranking controls, unknown/network-failure states, disabled plugin restoration, cached Back navigation, and mixed/all-blocked discovery carousels. Do not claim Linux support based on a Windows build.
5. **Commit, rebuild and verify one consistent identity.** The root archive still identifies `dev.wyatt.ai-disclosure-filter` / Wyatt, while the current manifest identifies `dev.zanedb.ai-disclosure-filter` / Zane Dragonborn. Both say 0.7.12. The isolated audit build proves the current manifest packages successfully, but does not update that stale root archive or the installed plugin. Settle the permanent ID; an ID change can create a separate install/configuration namespace. Migration matters if distributing upgrades to users of the old ID. The old-ID delete in Lua removes a malformed setting key, not the old plugin or a migration of its configuration.

### Quality corrections and recommendations

- **Formatting failure:** `npm run format:check` currently reports `frontend/information.tsx`. Format that file without changing its manually edited wording, then rerun the check. Formatting is a project quality gate, not a separately stated directory policy.
- **Performance measurement needed:** detection scans document-wide links and walks computed styles (`steam/surfaces.ts`); document-wide observers can trigger rescans. Provider requests are bounded, but CPU/layout cost on large personalized pages has not been benchmarked here. Measure and scope scans if results warrant it; do not claim a demonstrated performance bug without measurements.
- **Disable/re-enable deserves explicit live coverage:** `webview/preload.ts` uses a three-second backend lease and four-second timeout, with cleanup on failure. This intentionally restores presentation on backend loss, but also stops the current session after a transient failure. Confirm recovery expectations and whether open pages need refresh after re-enabling.
- **Finish support presentation before release:** the GitHub report button remains disabled with an empty URL by prior request. This is intentional, not a security issue. Once a public tracker exists, enable a real support route or clearly explain its unavailability. Add current screenshots to the README; none are embedded now.
- **Update historical documentation links/claims:** `docs/release-review.md` records the older v0.7.8 audit, with a later correction for Tabs. Treat it as history, not current UI certification. Use this report for the present checklist.
- **Not a submission blocker by itself:** Wishlist AI sorting remains absent and is documented. An unimplemented optional enhancement is acceptable if not advertised as available. Likewise, incomplete discovery coverage is disclosed and should be tested rather than represented as guaranteed.

## Code safety and architecture findings

The reviewed application code has no shell execution, arbitrary user-controlled network URL, cookie read, dynamic code evaluation or remote script injection. Public API/HTML requests omit credentials, validate App IDs and response identity, and treat unresolved results as visible. Retrieved disclosure/title text is inserted as text, not executable HTML. The only child-process use found is the local packaging script invoking the existing Starlight tool.

Request batches coalesce up to 40 IDs with two batches in flight. HTML fallback has four slots, ten-second timeouts and HTTP cooldown handling. Cache/history/filter inputs are bounded. Stop routines disconnect observers, cancel queued/provider requests, remove plugin UI and restore presentation attributes. Carousel/Wishlist adapters preserve native data and indices rather than submitting membership or rank writes. No paid backend or telemetry endpoint was found. These are positive code findings, not a guarantee against every runtime or security defect.

Compatibility risks remain: hashed Steam selectors, English classification rules, US/English public data context, experimental/virtualized layouts and optional page-global carousel/jQuery helpers. The README explains these limitations. The public structured disclosure field is observed Steam behavior, not an API stability promise.
